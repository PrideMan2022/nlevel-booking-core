# nlevel-booking-core

Логика записи из приложения NLeveL, сети детейлинг-центров в Екатеринбурге. Приложение написано на Flutter и Firebase, здесь вынесена та часть, которая не зависит ни от того, ни от другого: чистый Dart без внешних пакетов, всё покрыто тестами.

## Что внутри

- `slots.dart` - получасовая сетка записи. Работа на 5 часов, начатая в субботу вечером, раскладывается по слотам, переходит через закрытие салона и пропускает воскресенье.
- `business_time.dart` - время салона. Салон живёт в UTC+5 без перехода на летнее время, а телефон клиента может быть где угодно. Абсолютные моменты считаются от фиксированного смещения, поэтому сортировка записей не зависит от часового пояса устройства.
- `phone_ru.dart` - российские номера: `89991234567`, `+7 (999) 123-45-67` и `9991234567` приводятся к одному виду. Есть маска для поля ввода.
- `search_tokens.dart` - префиксные токены для поиска по имени и телефону в Firestore, где нет поиска по подстроке.

## Запуск

```bash
dart pub get
dart analyze
dart test
```

## Пример

```dart
final plan = NLevelTime.buildPlan(
  startDate: DateTime(2026, 8, 8), // суббота
  startSlot: '20:30',
  durationMinutes: 60,
);
// 2026-08-08 20:30
// 2026-08-10 10:00  <- воскресенье пропущено
```

## Что сделано осознанно

Воскресенье как выходной и часы работы 10:00-21:00 заданы константами в `slots.dart`. Для другого салона их достаточно поменять в одном месте.

Если время начала не попадает в сетку, оно подтягивается вперёд к ближайшему слоту. Назад не сдвигаем никогда: раньше из-за этого запись съезжала на полчаса.

Остальной код приложения (экраны, роли, push, кабинет мастера) в репозиторий не входит.
